## 一句話美學

**安靜、精確、高信任的專業儀器——不是 AI 玩具。**
表面極簡，內部複雜；顏色只為語義服務，永不裝飾。

## 1. 色彩系統（唯一真相源：os2.css `:root`）

| 用途 | 變量 | 值 | 規則 |
| --- | --- | --- | --- |
| 主墨/背景/卡片 | `--ink / --bg / --card` | 亮暗雙套 | 全部界面元素必須引用變量，**禁止新寫十六進制** |
| 分區五色 | `--a(--purple) / --b(--lime-deep) / --c(--blue) / --d(--orange) / --e(治理灰)` | #ce82ff / #58cc02 / #1cb0f6 / #ff9600 / #a0a4a2 | A產品線/T工具/R研究/I基建/Fork 各佔一色，不得挪用 |
| 深紫輔助 | `--purple-deep` | #7c3aed | 僅用於 Notion 語義，別再出現第三種紫 |
| 品牌深綠 | `--forest / --lime` | #163300 / #9fe870 | hero/lock 卡深色畫布專用 |
| archify 控制台 | slate/cyan 系 | #020617/#0F172A/#22D3EE/#34D399/#A78BFA | **自成體系，禁止換成 --vars**（地圖暗色畫布的語義色） |
| 風險紅 | `--red` | #ff4b4b | 僅錯誤態 |

**新規則**：寫任何樣式前先找變量；找不到就加變量，不寫裸值。唯一例外：`<canvas>`/靜態 SVG 字符串（CSS 變量進不去），此時用 BOARD_META 的 hex 雙軌並加註釋。

## 2. 按鈕系統（4 變體 + 1 暗色系，v0.3 收斂完成）

| class | 長相 | 用途 | 規則 |
| --- | --- | --- | --- |
| `.btn-duo` | lime 3D（box-shadow 0 4px 0） | **每屏只有一顆**主 CTA | 連接/同步/部署類 |
| `.btn-duo.ghost` | bg-soft 底 | 次操作 | 斷開/重置/管理/「先看 demo」 |
| `.btn-duo.sm` | 12px 字 / 6px 13px | 卡片內小空間的主次操作 | 狀態卡、connCards |
| `.btn-duo.blue` | 藍色變體 | 強調次操作 | 少用 |
| `.al-btn`（+.primary/.success/.ai） | mono 12 / r8 / 暗色邊 | **只在 archify 暗色控制台內** | 導出/探測/播放/AI 判讀 |
| `.lt-tab` / `.bs-btn` | 膠囊 / 小方 | 標籤頁 / 選擇 chips | 各自專屬，不外借 |

**禁令**：新按鈕不許寫 inline padding/border-radius；`<a class="btn-duo">` 不需要 `text-decoration:none`（os2.css 已有）；disabled 態用屬性不用 opacity inline。

## 3. 圓角五檔（v0.3 起全站只允許這五檔）

| 檔 | 變量 | 值 | 適用 |
| --- | --- | --- | --- |
| XS | `--r-xs` | 7px | kbd、badge、小控件 |
| S | `--r-sm` | 10px | 輸入框、小按鈕 |
| M | `--r-md` | 14px | 卡片、主按鈕、toast |
| L | `--r-lg` | 20px | 大容器（liveMapPanel） |
| XL | `--r-xl` | 26px | hero、lock-card |
| pill | 999px/50% | — | chip/頭像/圓點 |

Logo 圓角 = **尺寸 × 25%**（26px→約7px、64px→16px），統一用 `border-radius:25%` 寫法。

## 4. 字號階梯（12 種 → 9 種）

`10 / 11 / 12 / 13.5 / 15 / 16 / 19 / 24 / 32`（+hero 大字）
- 12 = 事實上的 small 標準（meta/輔助）
- 13.5 = 正文小號（body-sm）
- 15/16 = 正文；19 = 小標題；24/32 = 區塊標題
- **禁止** 11.5/12.5/13/14 這類碎值；歡迎語類大字只出現在登錄首屏（h1 28 / 正文 15，兩處實現必須同值）

## 5. 動效（MotionSites 借來的三原則 + archify 約束）

1. **快而輕**：所有 transition 140–200ms；入場 340ms 內結束
2. **交錯而有序**：切頁時 spec-grid 子元素 40ms 階梯延遲（.page.show 已內建）
3. **尊重系統**：`prefers-reduced-motion: reduce` 下全部動效關閉（已內建）
4. **禁止**：彈跳、旋轉、視差滾動、3D 變換——那是 MotionSites 賣的炫技，不是我們的儀器感

## 6. 組件狀態完備性檢查單（每次加組件過一遍）

- [ ] 默認態 + hover + active + disabled 四態都有樣式
- [ ] 加載態（骨架或「載入中…」）+ 空態（引導文案 + 出口按鈕）+ 錯誤態（人話 + 修復路徑）
- [ ] 亮色/暗色主題都檢查過（切 🌓 看一遍）
- [ ] 移動端 375px 不溢出
- [ ] 通知走 `toast(msg, kind)`，不許 alert
- [ ] 顏色/圓角/字號全部來自本文檔的檔位

## 7. Tauri 封裝預告（v2 分銷形態）

面板是純靜態 + 單 Worker，Tauri 壳只需：WebView 加載同一份 UI + 把 `/api/*` 改指向本地 sidecar（Rust 轉發）+ KV 換成本地 SQLite。**UI 層零改動**——這就是為什麼現在就把美學釘死：多平台分銷時，一致性就是品牌。

## 8. 多用戶數據隔離（淘寶購物車問題的答案）

自部署形態下：**每個人 fork 部署自己的實例** = 每人自己的 KV = 每人自己的會話 = 天然隔離（一人一店，而不是一店多購物車）。
未來集中托管版（v2）才需要「一店多用戶」：那時每個登錄用戶一個 session，KV 鍵前綴 `user:<id>:` 分區，用 Supabase/Clerk 做帳號層。**UI 不變，只是後端換艙。**
