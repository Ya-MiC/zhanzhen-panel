🧮 評分算法

Skill 3.0 · 11 因子 → FinalSPI · 選倉庫看完整計算 · 頁尾有 Starred 候選評估（含立刻可做的整合動作）

公式

C 能力圈 P 複利性 L 槓桿性 S 戰略一致 R 逆轉重要 M 護城河 D 差異化 Q 可理解性 E 道德合規 T 維護負擔(越高越差) U 不確定性(越高越差) AVS = 0.14C + 0.14P + 0.14L + 0.12S + 0.10R + 0.10M + 0.10D + 0.08Q + 0.08E GRS = 0.40T + 0.35U + 0.25(10 − E) SPI = 10·AVS − 5·GRS ForkPenalty = 0 / 6 / 12 / 20（按原創程度） FinalSPI = max(0, SPI − ForkPenalty)

資產角色（8+1）

CORE-ASSET

標準/知識/總控/品牌 → 保護維護、跨庫引用。

BUSINESS-ENGINE

可形成收入 → 驗證需求、補 MVP。

LEVERAGE-TOOL

多專案重用 → 文檔化、模組化、Skill 化。

INFRASTRUCTURE

部署/網路/安全 → 保持私有、最小文檔。

LEARNING-ASSET

學習/PoC → 完成後升級作品或封存。

RECORD-ASSET

歷史/交接 → 原樣保存，不任意重構。

EXTERNAL-REFERENCE

Fork/上游 → 記錄來源授權，非商業宣稱。

HUMAN-REVIEW

不明 → 只盤點保留，等人類裁決。

不可違反原則

  1. 1
    Understand before organize
    先理解再整理。
  2. 2
    Evidence before conclusion
    先證據再結論。
  3. 3
    Preserve before deleting
    先保留再考慮刪除。
  4. 4
    Human approval before consequential action
    重大動作必須人類批准。
  5. 5
    Risk before commercialization
    先風險再商業化。
  6. 6
    One responsibility, one canonical home
    每種資料只有一個權威來源。
  7. 7
    Proof, not promises
    公開展示以可重現證據支撐。

決策閘門 G1–G5

  1. G1
    理解
    已讀 README、描述、近期提交與 Issue？
  2. G2
    證據
    有原始檔、測試、研究資料或可追溯連結？
  3. G3
    歸屬
    有唯一責任倉庫與系統？
  4. G4
    風險
    私密性、授權、憑證、上游限制查過？
  5. G5
    人類批准
    刪除/改名/公開/付款/憑證/商業承諾 → 必須你批准。

名詞 30 秒

Repository

一個專案的檔案+歷史，你有 … 個。

Commit

一次存檔，可回溯任何版本。

Branch → PR → Merge

草稿線 → 修改申請 → 合併 = 批准。

Issue

討論串/裁決單；留字母=投票，機器人自動收。

Star

收藏別人的專案，連接後自動入畫廊並按領域分區。

Token

程式存取鑰匙，讓 Agent / 工具代表你操作 GitHub。
