## 🎯 核心定位

**湛箴不是另一個雲端硬碟。**

它是一個本地優先（local-first）的跨端工作面板：用戶授權後，將不同平台中的文件與資料放到同一個清晰、可操作的工作視圖。文件按照副檔名自動歸入三個**虛擬資料夾**；分類不會移動或改寫原始文件。

| 虛擬資料夾 | 自動識別格式 | 主要操作 |
|---|---|---|
| 📄 PDF | `.pdf` | 閱讀、搜尋、標註（後續） |
| 📊 表格 | `.xlsx` `.xls` `.csv` | 瀏覽工作表、分析資料（後續） |
| 📝 文檔 | `.docx` `.doc` `.md` | 閱讀、AI 協作、Diff 修訂（後續） |

## ✨ 核心能力

- 📄 **PDF 原生預覽**：在面板直接閱讀 PDF，不必在多個應用之間跳轉
- 📊 **Excel / xlsx 原生預覽**：表格、工作表與資料內容在面板內查看
- 📝 **Docx 原生預覽**：將 Word 文檔渲染為可閱讀的視圖
- 🗂️ **自動分類**：依副檔名建立 PDF、表格、文檔三種工作視圖
- 🔐 **OAuth 授權連接**：用戶自行授權自己的服務帳號；產品不要求交出密碼
- 🔄 **多端狀態同步**：同一帳號在電腦與手機上使用時，維持已連接服務與同步狀態
- 📴 **離線可讀**：已同步過的文件可在離線時打開，採本地快取
- 🌓 **淺色 / 深色模式**：以湛箴的藕粉、深灰紫與留白語言保持一致

## 🔌 數據連接器

每個連接器都應採用獨立 adapter 模組，統一實作 `fetchFiles()` 與 `getFileContent(id)`；新增平台時不需要重寫面板核心。

| 服務 | 接入方式 | 優先級 | 說明 |
|---|---|---:|---|
| 🐙 GitHub | GitHub OAuth | P0 | 登錄與讀取用戶授權倉庫中的文件可共用授權流程 |
| 📈 Google Sheets / Drive | Google OAuth | P1 | 讀取試算表與雲端文件元資料 |
| 🟣 Notion | Notion OAuth Integration | P1 | 讀取已授權頁面與資料庫 |
| 💎 Obsidian | 本機 Vault 選擇 | P1 | 不使用 OAuth；桌面端由使用者選擇本機 Markdown 資料夾 |

> 🔒 原始文件盡量由桌面端或用戶授權的服務直連讀取；後端只保存必要的帳號、連接與同步狀態，不把用戶文件當作平台集中存儲內容。

## 💻📱 跨端策略

| 端 | 第一階段方案 | 為什麼 |
|---|---|---|
| 💻 Windows / macOS / Linux | **Tauri 桌面應用** | 安裝包小、可讀取本機 Obsidian Vault、可使用 SQLite 離線快取 |
| 📱 手機 | **PWA** | 手機瀏覽器可直接使用並加入主畫面；先用較低成本驗證需求 |
| 🔄 同步 | Cloudflare Workers + D1 或 Supabase | 僅同步帳號、連接器設定與資料版本；用戶仍掌控各平台授權 |

在沒有真實使用者之前，不提前投入 React Native 或 Tauri Mobile；先讓 PWA 成為手機端驗證方案。

## 🤖 AI 共創

AI 不應取代人的最終判斷，而是整理材料、給出草案、協助分析與呈現可審核的修訂。

可選角色：`PI（預設）` · `行業專家` · `法律顧問` · `數據分析` · `財務管家` · `自定義`

- ✍️ 對選定文檔發起協作請求
- 🔎 根據角色提供不同的分析與檢查視角
- 🔁 以 Diff 顯示建議，讓使用者保留、刪除或修改，不直接覆寫原文
- 🧠 後續才做 AI × AI 交叉驗證；它不是 M0 的阻塞功能

## 🧩 四個工作環節

1. 👥 **人 + AI 共創**：整理素材、寫初稿、做 SOP、畫流程圖
2. 🤖↔️🤖 **AI × AI 自治會議**：多智能體提出觀點、反駁與驗證，輸出結構化報告
3. 🗳️ **人類議事**：不注入 AI 結論，只做價值判斷、重大決策、投票與簽核
4. 🔁 **人工修正與反饋**：透過 Diff、標準化規則與回寫知識庫，使系統持續改進

## 🛠️ 技術選型

| 類別 | 建議 | 用途 |
|---|---|---|
| 前端 | Vue 3 或 React + Vite | 延續既有 Vite 生態，快速做出跨端 UI |
| 桌面封裝 | Tauri | 提供 Windows/macOS/Linux 安裝包與本機能力 |
| 本地資料 | SQLite + Tauri SQL plugin | 離線快取、連接器資料與本機索引 |
| PDF | pdf.js | PDF 預覽 |
| 表格 | SheetJS (`xlsx`) | xlsx/xls/csv 解析與渲染 |
| Word | mammoth.js 或 docx-preview | docx 預覽 |
| 雲端狀態 | Cloudflare Workers + D1 或 Supabase | 帳號、連接器設定、同步游標；不集中保存原始文件 |

## ⚠️ 執行規則

這一節是給 Cursor、Claude Code、Codex、DSH、Inkling 或其他執行型 Agent 的工作合同。

1. **按里程碑實作**：不要一次完成所有功能。完成一個可驗收小步，再做下一步。
2. **每個功能一個 PR**：PR 說明必須包含改動文件、功能行為、環境變數與本地測試方法。
3. **視覺以設計規範為準**：先讀 [`docs/DESIGN_TOKENS.md`](docs/DESIGN_TOKENS.md)，不得任意替換湛箴配色或品牌語言。
4. **秘密絕不入庫**：所有 OAuth Client ID、Secret、Token 只進 `.env`，範例只放 `.env.example`；不得提交真實值。
5. **不直接改 main**：任何代碼/配置變更先開 branch + PR；在 PR 中附驗證結果。
6. **不做未授權寫入**：不得自行發布、公開倉庫、刪除資源、變更付費設定或要求超出需求的 OAuth 權限。
7. **每次交付固定格式**：`✅ 已完成：...`、`🧪 驗證：...`、`➡️ 下一步：...`、`⚠️ 需要使用者決定：...`。
