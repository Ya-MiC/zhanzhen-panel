# Ya-MiC 總控作業系統 — 用戶故事 (User Stories)

## 用戶角色定義

| 角色 | 描述 | 核心痛點 |
|---|---|---|
| **資產治理者（Ya-MiC 本人）** | 擁有 59+ GitHub 倉庫、42 個 Star，需要視覺化面板管理 | GitHub 原生界面無法一眼看清資產全貌、分類混亂、無法快速定位 |
| **小白用戶（未來擴展）** | 不懂 GitHub 安裝/命令行的初學者 | 被 GitHub 的技術門檻嚇退，需要「下載就能用」的圖形界面 |
| **審計師（湛箴產品線）** | 需要 OCR 識別發票、整理憑證、生成審計報告 | 現有工具（鼎新諾）昂貴、封閉、無法本地部署 |

---

## 核心用戶故事（按優先級排序）

### US-001：作為資產治理者，我想要一眼看清所有倉庫的分類狀態，以便快速定位目標項目

**驗收標準：**
- [ ] 面板加載後，59 個倉庫按「十大主定位」分組顯示
- [ ] 每組有可摺疊的標題欄（點擊展開/收合）
- [ ] 每個倉庫卡片顯示：名稱、簡介、語言、star 數、fork 數、最後更新時間
- [ ] 卡片顏色按 FinalSPI 評分區分（A 級綠色、B 級藍色、C 級黃色、D/E 級紅色）

**當前狀態：** ✅ 已實現（`gallery.html` 讀取 `public/data/portfolio.json`）

---

### US-002：作為資產治理者，我想要倉庫工作區和 Star 工作區分開顯示，以便分別管理

**驗收標準：**
- [ ] 頁面頂部有兩個分頁標籤：「我的倉庫」/「我的 Star」
- [ ] 切換分頁時，下方內容區域無縫切換（不重新加載頁面）
- [ ] 兩個分頁各自維護自己的摺疊狀態（倉庫區展開時，Star 區可以是收合的）
- [ ] 每個分頁有自己的篩選器（按語言、按評分、按主定位分類）

**當前狀態：** ❌ 未實現（用戶明確訴求，待開發）

---

### US-003：作為資產治理者，我想要面板數據與 GitHub 實時同步，以便看到的簡介/星數是最新的

**驗收標準：**
- [ ] autopilot 每小時自動執行一次（GitHub Actions 定時任務）
- [ ] 同步範圍：所有 59 個自有倉庫 + 42 個 Star 的元數據（名稱、簡介、語言、star 數、fork 數、Topics、last commit）
- [ ] 同步後自動提交到 `public/data/*.json`，觸發 Netlify/Cloudflare Pages 重新部署
- [ ] 面板加載時顯示「最後同步時間：YYYY-MM-DD HH:mm」

**當前狀態：** ⚠️ 部分實現（autopilot 每 5-7 小時執行一次，但 `repositories.yaml` 不會自動更新分類）

---

### US-004：作為資產治理者，我想要對「不確定的倉庫」標記為 Human Review，以便後續集中處理

**驗收標準：**
- [ ] 有一個獨立的「待裁決」視圖，只顯示 15 個 Human Review 項目
- [ ] 每個項目顯示：倉庫名稱、當前評分、標記原因（無簡介/無 Topics/ fork 但用途不明）
- [ ] 有「裁決」按鈕：點擊後可選擇歸類到十大主定位之一，或標記為「封存」
- [ ] 裁決後自動更新 `repositories.yaml`，並觸發 autopilot 重新評分

**當前狀態：** ❌ 未實現（DDL 2026-09-05，剩餘 0 天）

---

### US-005：作為小白用戶，我想要下載一個 .exe 或 .dmg 安裝包，安裝後就能看到面板，以便不用學 Git 命令

**驗收標準：**
- [ ] 提供 Windows / macOS / Linux 三平台安裝包
- [ ] 安裝後自動打開瀏覽器，指向本地運行的面板（`http://localhost:8080`）
- [ ] 首次啟動時引導用戶輸入 GitHub PAT（Personal Access Token）
- [ ] 面板本質是 Electron 包裝的 `index.html`，所有邏輯與網頁版一致

**當前狀態：** ❌ 未實現（未來擴展方向）
